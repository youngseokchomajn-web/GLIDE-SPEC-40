# First Product Concept Selection Gate — v0.1

Date: 2026-09-13

## Purpose

현재 단계의 목표는 제품을 시험하거나 제형을 확정하는 것이 아니다.

목표는 한국 러너 primary research를 통해 **첫 제품이 집중해야 할 하나의 beachhead scenario**를 선택하는 것이다.

현재 working architecture는 다음과 같다.

- Beachhead problem: **Long-Run Friction Shield**
- Category logic: **Endurance Skin Protection**
- Core environmental condition: **TIME × MOTION × ENVIRONMENT**
- Sweat/heat/humidity는 중요한 조건 변수이지, 현재 단계에서 독립적인 제품 category로 확정하지 않는다.

## 1. Decision question

설문이 답해야 하는 질문은 "어떤 anti-chafe 제품이 가장 인기인가?"가 아니다.

핵심 질문은 다음이다.

> **어떤 장거리 러닝 상황에서 기존 피부 보호 해결책이 반복적으로 충분하지 않거나 불편하며, 그 문제를 해결할 경우 사용자가 실제로 기존 해결책을 바꿀 만큼 가치가 있는가?**

## 2. Required evidence

### Gate A — High-value failure scenario

다음 조건을 동시에 본다.

- 반복적으로 발생하는가
- 장거리 러닝에서 의미 있는 불편인가
- 특정 거리/시간/환경/의류/장비 조건과 연결되는가
- 단순히 개인 취향이 아니라 명확한 failure moment가 존재하는가

### Gate B — Existing-solution failure

현재 해결책을 무엇을 쓰는지보다 **왜 충분하지 않았는지**를 본다.

예:

- protection failure
- sweat/water failure
- migration
- reapplication burden
- reachability
- sensory/cleanup
- transfer/staining
- clothing/equipment interaction

### Gate C — Switching trigger

실제 제품 선택은 문제의 존재만으로 발생하지 않는다.

확인할 것:

- 실제로 다른 solution으로 바꾼 경험
- 바꾸게 만든 trigger
- 현재 solution을 계속 쓰는 이유
- topical 대신 tape/apparel/equipment를 선택하는 이유

### Gate D — Segment concentration

전체 응답자 평균보다 다음 segment에서 문제가 집중되는지를 본다.

- 21.1 km+
- marathon
- ultra
- long-duration runners
- road/trail
- hot/humid exposure
- heavy-sweat runners
- recurring failure users
- relevant anatomical/interface groups

Segment별 차이는 **시장 전체 prevalence**로 표현하지 않는다. 표본 설계와 대표성 한계를 함께 기록한다.

### Gate E — Economic relevance

문제가 존재하더라도 돈을 지불할 이유가 없다면 첫 제품 문제로서 약하다.

확인할 것:

- 현재 solution에 실제 지출
- 연간 구매량/지출
- tape/apparel/equipment에 추가 지출
- switching 경험
- 가격 민감도
- 현재 solution 유지 의향
- neutral concept에 대한 선택 의향

### Gate F — Concept fit

최종 후보는 다음 조건을 만족해야 한다.

1. 현재 evidence와 연결된다.
2. 특정 runner와 특정 상황으로 설명할 수 있다.
3. 기존 대체재와 경쟁 이유가 명확하다.
4. 제품 개발로 해결 가능한 문제다.
5. 향후 Endurance Skin 카테고리로 확장 가능하다.

## 3. Candidate scoring

각 후보를 1–5점으로 평가한다.

| Dimension | Question |
|---|---|
| Problem intensity | 문제가 얼마나 심각한가? |
| Recurrence | 반복적으로 발생하는가? |
| Existing-solution gap | 기존 해결책의 한계가 명확한가? |
| Switching evidence | 실제 switching 행동이 있는가? |
| Economic value | 지불/구매 행동과 연결되는가? |
| Segment clarity | 초기 beachhead user를 명확히 정의할 수 있는가? |
| Solvability | 화장품/사용경험 설계로 해결 가능한가? |
| Differentiation | 단순 generic anti-chafe와 구분되는가? |
| Expansion fit | Endurance Skin architecture와 연결되는가? |

점수 자체가 자동으로 제품을 결정하지 않는다. **정성 evidence와 contradiction을 함께 검토한 뒤 판단**한다.

## 4. Decision outcomes

### SELECT

하나의 beachhead scenario를 first-product concept의 중심으로 채택한다.

### CONDITIONAL SELECT

문제는 유망하지만 특정 segment 또는 행동 evidence가 부족하다. 제한된 추가 primary research 후 결정한다.

### HOLD

문제 신호는 있으나 switching/economic value 또는 정의가 부족하다.

### REJECT

반복 evidence가 약하거나 기존 대체재가 더 적합하거나 제품으로 해결할 이유가 부족하다.

## 5. What the gate must NOT decide

이 gate에서는 다음을 결정하지 않는다.

- 최종 formula
- 특정 ingredient
- stick/balm/cream/gel 등 최종 format
- 정확한 지속시간
- superiority claim
- clinical efficacy
- regulatory claim eligibility
- final package
- final retail price

이들은 beachhead scenario가 선택된 뒤 별도 개발 gate에서 결정한다.

## 6. Expected output

한국 primary research가 끝나면 다음 문서 수준의 결론을 만든다.

> **First Product Beachhead:** [specific runner + specific situation]
>
> **Failure moment:** [when/where/how current solution becomes unacceptable]
>
> **Current workaround:** [product / tape / apparel / equipment / none]
>
> **Switching trigger:** [what would cause a change]
>
> **Value hypothesis:** [why solving this is worth paying for]
>
> **Open technical hypothesis:** [what later testing must verify]
>
> **What we are explicitly not claiming:** [efficacy / superiority / duration / prevalence etc.]

## 7. Research sequence after this gate

1. Run small pilot of the existing field instrument.
2. Check whether respondents naturally cluster around the candidate failure scenarios.
3. Remove questions that duplicate already-saturated global evidence.
4. Expand to the planned Korean sample only if the pilot instrument is discriminating.
5. Select one beachhead scenario.
6. Update `first_product_concept.md` to v0.3.
7. Record the decision and rejected alternatives in `decision_log.md`.
8. Only then begin formulation and technical validation planning around the selected scenario.

## Evidence boundary

Primary research establishes customer/problem/behavior evidence. It does not establish objective product performance, clinical efficacy, exact duration, superiority, or regulatory eligibility.
